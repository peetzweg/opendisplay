and all 103 tests again using the extracted installer's bundled runtime.

artifact, not a replacement of the published 0.0.17 download.

Earlier failures had two causes:

- Build 39204352939 could not locate the pinned libplist installation. Explicit
  CMake prefix/static-library paths fixed this before the successful build.
- Build 39204801295 failed OpenSSL 3.6.3's `check_pc_flood` test inside
  `70-test_quic_radix.t`. A later pass did not resolve this intermittent failure.

The QUIC test checked counters immediately after writing a client packet.
Writing does not guarantee that the server has processed the packet. Running
the original test locally with its recorded seed, `1792388392`, reproduced one
failure in 40 runs. An attempted payload-read barrier was rejected because the
flood test does not guarantee delivery of that payload.

`scripts/sync-openssl-test.js` instead applies a narrowly matched build-time test
patch: process server events and yield through the existing harness while
counters remain zero. The exact 16-challenge/one-response assertions and the
harness's three-second deadline remain unchanged. The patch refuses unexpected
or already-patched source. No production OpenSSL source is modified, tests are
not skipped, and failures are not automatically retried into success.

The corrected native test passed 100 consecutive local runs with the recorded
seed. The `libcrypto.a` checksum was identical before and after rebuilding the
test executable. Two patch-verification tests cover synchronization, retained
assertions and rejection of unexpected source. The complete GitHub dependency,
bridge, packaging and extracted-runtime checks must pass on the resulting clean
commit before that candidate can proceed to physical validation.

The release gate still requires fresh-installer home LAN and restricted-network
Tailscale testing, return-home recovery, upgrade/reconnect/rotation/audio/resume
and uninstall records for the exact resulting ZIP. Passing CI alone does not
authorize publishing it. The existing working installation is unchanged.
